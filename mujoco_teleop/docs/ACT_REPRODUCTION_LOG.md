# ACT 训练与部署复现记录（第 3、4 部分）

## 范围与来源

继续使用 Every-Embodied 固定提交 `14d7c6c93debf01419b21e50b649a06f15881c38`
中的 `3.train.ipynb` 与 `4.deploy.ipynb`。两个原始 Notebook 已保留在
`vendor/every_embodied/`，原始文件哈希加入 `upstream_manifest.json`。
LeRobot 仍固定为 `10b7b3532543b4adfb65760f02a49b4c537afde7`。

本次训练 ACT 模仿学习策略；ACT 本身不是带语言理解的 VLA。仅使用场景图像和末端位姿，
不把任务文本、时间、阶段编号、杯盘真值位置或示教未来动作作为部署输入。

## 1. 环境准备

- 使用已有 my_env Python 3.10.21 和 PyTorch 2.14.0+cu130 / torchvision 0.29.0+cu130。
- 新增 safetensors 0.5.3、imageio 2.37.0 到项目 `.deps`，不修改 my_env/base 的已安装包。
- 从 torchvision 官方地址缓存 ResNet18 ImageNet 初始化权重 `resnet18-f37072fd.pth`，
  核对 SHA-256 前缀。权重缓存留在 `.downloads/torch`，不放进 Git。
- `scripts/prepare_act.py` 可重新完成 ACT 附加依赖和初始化权重准备。

## 2. 第 3 部分：实现训练入口

- 训练数据来自上一阶段本机生成的 `data/scripted_demo_004`：1 个成功回合、602 帧、20 Hz。
- 输入：`observation.image`（3×256×256），`observation.state`（6 维末端位姿）。
- 输出：连续 10 帧、每帧 7 维的绝对关节目标和归一化夹爪命令。
- 沿用 ResNet18、512 隐藏维、4 层 Transformer encoder、1 层 decoder、VAE 与 KL 权重 10。
- Adam 学习率 1e-4，图像高斯噪声标准差 0.02；正式训练 5000 步，批量 64。
- 使用 BF16 AMP 适配本机 GPU；实际配置、数据哈希、显存峰值和耗时由训练报告保存。
- 小数据集的图像以 uint8 缓存在 GPU，随机抽取训练批次，避免 Windows DataLoader 多进程开销。
- 动作块在回合尾端填充，不越过回合边界；对应的 padding mask 传入原始 ACT loss。
- 输出 `best/` 和 `final/` 的标准 config.json / model.safetensors，以及训练日志和曲线。
- 已有训练输出目录不会被覆盖，再次训练必须使用新的输出目录。

## 3. 评估修正

原始 Notebook 的一个评估片段把包含真值 `action` 的批次交给策略。
该版本 ACT 模型只要发现 `action`，即使在 eval 模式下也会通过 VAE 编码真值未来动作。
本项目的离线评估显式只传入观测，使用零 latent，不把训练目标泄漏到推理过程。

离线 MAE 是“给定示教当前观测”的动作误差；它不代表模型自己运行时的抓放成功率。
本次只有一个训练回合，因此离线指标属于训练回合拟合，没有留出回合或泛化成功率主张。

## 4. 第 4 部分：部署入口

- 从本地训练 checkpoint 严格加载全部权重；缺文件、类型不匹配或权重不完整时失败。
- 修正旧版配置反序列化：通过 `PreTrainedConfig` 识别 JSON 的 `type=act`，
  避免直接用 ACTConfig 读取时触发 `type` 字段错误。
- 部署时不再下载 ImageNet 权重，直接使用训练 checkpoint 保存的骨干网络权重。
- 每步读取实时相机图像和末端位姿，由 ACT 神经网络产生动作并推进 0.05 秒 MuJoCo 仿真。
- 支持教程的时间集成（系数 0.9）和每次执行 10 步动作块两种模式。
- 每个 trial 调用 policy.reset() 清空动作队列或时间集成状态。
- 保存逐帧动作/状态、任务判定、杯子实际抬升、末帧图片、动画和部署报告。
- 额外记录“抓起超过 10 厘米并满足放置判定”的结果，与单独上游位置判定区分。
- 没有使用示教动作回放、IK 脚本接管或隐式吸附约束。

## 5. 实际验证记录

- 20 步训练基准通过：模型约 5155 万参数，batch 16，显存峰值约 1413 MiB。
- ACT 专项检查覆盖动作块不跨回合、未来动作不泄漏、checkpoint 往返预测一致、
  缺权重不能回退为随机初始化，以及改变预测窗口时保留训练权重。
- 原有 5 项采集/回放回归检查仍通过。

### 原教程配置的完整训练

- 5000 步完成，batch 64，chunk size 10，耗时 1005.49 秒（约 16.76 分钟）。
- GPU 显存峰值 2878.84 MiB，模型参数 51,552,181。
- 训练回合的离线总体 MAE 从 0.364968 降为 0.004914；最终关节 MAE 0.004938 rad，夹爪 MAE 0.004767。
- 离线选出的 best 位于第 4500 步，总体 MAE 0.004556；第 5000 步 final 另外保留。
- best 和 final 分别在 chunk-10、ensemble-0.9 模式执行同种子 1000 帧闭环部署，四次均未抓放成功。
- 机械臂停在杯子上方，实际杯子抬升不足 1 mm。因此该配置只有离线拟合结果，不能声称 ACT 抓放复现成功。
- 训练报告、完整指标、曲线、权重哈希及四次部署报告保存在 `docs/act_baseline/`。

### 后续诊断与原生 ACT 长窗口验证

- 中间 checkpoint 的部署也出现类似停顿，排除“训练完成前未运行”的混淆。
- 单帧输入不包含时钟/阶段；原示教每段有 15 帧静止等待，闭爪阶段另外等待。
  这些近似相同的观测可对应不同的未来转移时机，可能导致短窗口策略停在平均动作附近。
- 曾尝试重新采集短停顿示教：杯子抬升约 0.209 m，但最终未放到盘子上，因此没有保存为成功训练回合，未用于训练。
- 保持原来的成功示教数据不变，使用 ACT 原生 100 步预测窗口（原实现的默认窗口长度），在已训练权重上继续优化。
- 所有共享权重严格继承；仅将动作 query 的位置嵌入线性插值到新长度，VAE 的固定位置编码使用新长度的确定性编码。
- 此扩展改变了窗口长度并增加训练步数，属于工程适配实验，不作为只改变窗口的严格消融实验。
- 部署仍只由 ACT 权重输出动作，不加入计时脚本、示教回放或 IK 接管。

### 100 步窗口实际训练与部署

- 从原配置第 4500 步 best 权重初始化，在相同 602 帧示教上继续训练 2000 步。
- batch 32、学习率 5e-5、chunk size 100、BF16，耗时 295.58 秒，显存峰值 2442.72 MiB。
- 最终训练回合关节 MAE 为 0.006920 rad，夹爪 MAE 为 0.006565；这比短窗口离线指标稍差，不能据此判定部署质量。
- 长窗口的离线 best 位于续训第 1500 步，实际未完成抓放，杯子最高抬升约 8.8 cm。
- 续训第 2000 步 final 权重完成了抓起和放置，因此后续实际部署选择 final，而不是离线 best。
- 早期宽松任务条件会在夹爪尚未充分松开时触发，因此最终确认额外要求：夹爪命令 ≤0.1、末端高度 ≥0.95 m、杯子抬升 ≥0.1 m，并连续满足放置条件 20 帧。

### 有窗口部署的 OpenGL 问题

- 第一次有窗口复测失败；检查实际相机图片发现纹理/透明度明显异常，而非仅根据动作猜测原因。
- 原始 viewer 仅在构造时设置 OpenGL 上下文；本地相机 Renderer 使用另一个上下文，调用 viewer 时未切回其窗口，污染了后续相机渲染。
- 在本地 `runtime.py` 的 show/close 中显式切换到 viewer 窗口上下文；上游 vendor 源码保持不变。
- 新增有窗口回归检查：显示一帧前后的双相机像素逐项一致，MuJoCo 积分状态逐项一致。
- 已有训练示教在无主窗口模式生成，没有受该问题影响。
- 修复前的有窗口失败报告也保存在 `docs/act_horizon100/`，不删除负结果。

杯子竖直姿态不在上游成功条件里；图像与详细位置指标一并保留供检查。
